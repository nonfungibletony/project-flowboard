feat(members): workspace-scoped member management (#44)

Backend
- New table: workspace_members (workspace_id FK, user_id FK, role, timestamps)
  - Unique constraint on (workspace_id, user_id) to prevent duplicates
- Migration: 0003_add_workspace_members.sql + journal entry
- Shared types: WorkspaceMemberSchema, CreateWorkspaceMemberSchema
- New API route: workspace-members.ts
  - GET /api/workspaces/:id/members — owners and members can view
  - POST /api/workspaces/:id/members — owner only; adds by email
    - Idempotent: returns existing member if already added
    - Validates user exists in system first
  - DELETE /api/workspaces/:id/members/:memberId — owner only
- Wired into index.ts under /workspaces/:id/members

Frontend
- New hook: useMembers(workspaceId?) — load, add by email, remove
- Rewrite Members page:
  - Workspace selector dropdown
  - Add member by email with validation hint
  - Member list with name, email, role badge, remove button
  - Handles empty states, loading, errors
- CSS: .member-actions, .form-label, .form-select, .hint-text

Security
- Only workspace owners can add/remove members
- All existing members can view the member list
- MVP assumption: all members have full access (role persisted but not enforced)

Closes #44
